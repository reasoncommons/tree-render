## Goal and done-check

Goal: anyone, human or agent, can get from "I have a question tree" to a share-quality image by the shortest path open to them, and the docs describe only what the renderer does today.

Done when:

- A stranger with Node 20 and Chrome goes from the README to a PNG of the bundled example in under 5 minutes, using commands checked on a fresh clone.
- An agent with the skill installed turns a pasted outline into a prepared tree and a rendered PNG reading only SKILL.md and CONTENT-GUIDE.md.
- PROMPT.md pasted into a fresh Claude.ai or ChatGPT chat with an outline gives back a prepared tree (Markdown + JSON) and, with no shell, a preview image.
- Every flag the docs mention appears in `--help`; no doc calls `river` the default or presents the canvas formats as current.

## Copy-paste prompt

**Options weighed.** (a) Run the real renderer: best output, but it needs a shell, Node and ideally Chrome. Claude Code, Codex and ChatGPT's code tool have the shell, but plain chat doesn't. (b) Hand-write the SVG from a spec: possible, but the model can't measure text, so wraps and spacing drift. It works acceptably only if the model writes code that measures text: an HTML artifact using canvas `measureText`, which Claude artifacts and ChatGPT canvas can both run. (c) The content step alone, which works anywhere and is where most of the value is.

**Recommendation.** Use one prompt with tiers. Always do (c). Then (a) if a shell is available. Otherwise (b), as a self-measuring HTML artifact labelled as a preview. Later, a hosted web renderer (see code changes) would replace (b) with "paste this JSON there".

Draft:

```text
Turn the material below into a share-quality tree diagram, using tree-render (https://github.com/reasoncommons/tree-render).

1. CONTENT. Make a prepared tree from my material. Compress my argument; never invent claims, drop qualifiers or change "should" to "does".
- Root: a plain question (≤ 8 words). Level 1: 3–5 assertions, not topics. Level 2: 2–4 short points under each (≤ 14 words). Two levels below the root.
- Each level-1 node opens with a bold lead (≤ 6 words) that stands alone as a heading; the rest of the sentence (≤ 12 words) qualifies it. Read alone, top to bottom, the leads should tell the argument.
- If my material reaches a conclusion, make it the last level-1 node, starting "So".
Show the tree as Markdown (H1 title; nested "- " bullets with 2-space indents; the first bullet is the root; **lead** in bold), then as JSON: {"title", "root": {"text", "lead"?, "children": [...]}}, where "lead" is the exact opening words of "text". List any wording you drafted rather than took from me.

2. RENDER, if you can run shell commands with Node 20+:
  git clone --depth 1 https://github.com/reasoncommons/tree-render && cd tree-render/skills/tree-render/render && npm install
  node bin/render.js tree.json --out out        # writes out/tree.svg and out/tree.png
Use --style coggle-thin|ribbon|dendrogram|lanes for other looks. The PNG needs Chrome (or set CHROME=/path); otherwise add --no-png and use the SVG. Exit code 1 means a branch crosses a label: shorten the text and render again. Never fix it by shrinking the type. Open the image and check it.

3. PREVIEW, if you can't run commands: make one self-contained HTML artifact that draws the tree as SVG, measuring text with canvas measureText, following these rules (Coggle's look):
- Left to right. Root in a #d0d0d0 box (radius 2.5, text #414141, 22px). Text: Arial/Helvetica, 15.3px at level 1, 13px below; bold lead at 700, the rest at 400; wrap at 260px.
- Each level-1 branch takes the next colour: #7aa3e5 #67d7c4 #9ed56b #ebd95f #efa670 #e68782 #e096e9 #988ee3. Children keep their parent's colour. Text colour = branch colour in HSL with saturation × 0.7 and lightness × 0.5.
- A branch is one stroked cubic (no fill, butt caps) from start (x0,y0) to end (x1,y1), dx = x1−x0, dy = |y1−y0|: c1 = (x0 + max(0.08dy + min(0.7dx, 600), 16), y0), c2 = (x1 − max((dx + min(0.6dy, 1200))/2, 8), y1). Width by level L (1 = root's children): max(2, (18·0.91^L + 2)/2), about 8.5px, then 7.8px, then 7.2px.
- Level-1 labels are right-aligned, ending 9px left of their junction, sitting just above (or below) the flat end of their branch. Leaves are left-aligned 4px right of a junction 54px right of their parent's junction. Siblings stack with 15px between text boxes, centred on the parent.
Say it is a preview, and that the exact render comes from step 2.

My material:
<paste your tree, outline or notes here>
```

The step 3 numbers come from docs/design/references/coggle-spec.md, adapted to the 22px root and 260px wrap we use. Before shipping, test the prompt in a fresh Claude.ai chat and a fresh ChatGPT chat, and fix what breaks.

## Small code changes for easy install (list only)

1. **Root package.json** with `bin: tree-render → skills/tree-render/render/bin/render.js`, `opentype.js` as a dependency, and a `files` whitelist (`skills/tree-render/**`, excluding `out/`). Then `npx -y github:reasoncommons/tree-render tree.md` works. Fonts resolve relative to the source (`src/coggle/text.js`), so they travel with it. Without a whitelist, npx fetches the whole 44 MB repo; with one, publishing to npm makes it about 2 MB.
2. **`--help`**: show the current static styles and flags first, and move the canvas engine's options under `--help-legacy`.
3. **`check`**: make it run the chosen style's collision check, or remove it from the docs and help.
4. **Chrome discovery** (`scripts/png.js`): also try `google-chrome`, `chromium` and `chromium-browser` on PATH, macOS Chromium.app, and Windows paths. Bigger option, worth a bead: a no-browser PNG path via `@resvg/resvg-js`, loading `fonts/` directly, which would drop the Chrome requirement.
5. **Skill without `npm install`**: once item 1 exists, SKILL.md calls `npx tree-render`, so `npx skills add reasoncommons/tree-render` (the repo already has the `skills/<name>/SKILL.md` layout) works with no second step.
6. **Hosted web renderer** (bead, not a docs blocker): a browser bundle of `src/coggle` and `src/styles2` on one page where you paste JSON and get SVG/PNG. That would be the best zero-install path, and PROMPT.md step 3 would point to it.
7. **Smoke test** that runs every command in the README and PROMPT.md, so the docs can't drift from the code.

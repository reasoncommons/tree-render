# Revision after Rufus's review — 2026-11-11

Rufus reviewed the 2026-11-07/08 design (Paper/Garden/Slate, shelf under the text, interactive web view) and the mood board. Verdict: **worse than v0.1**. This note records his feedback, the revised overall picture, and what we do now. It supersedes the direction in [the design brief](../design/2026-11-07-tree-visual-brief.md) and [spec](../design/2026-11-07-tree-visual-design.md) where they conflict.

## Feedback (Rufus, 2026-11-11, close to his words)

- **v0.1 is the best so far** ([q2-mindmap.png](../../archive/v0.1/planning/trials/mindmap/q2-mindmap.png)). Its strength was the *text*: terse, a hypothesis tree under a question root ("How fast should we develop AI?" → "Go at the speed of wisdom"), a bold lead and a lighter continuation ("**The world races** because it is caught in a collective action trap"), a "So…" branch. Its weakness was the *drawing*: branches too thin, not beautiful. "Rather than just fixing that, you need to actually think about what you're trying to do."
- **Two steps, like slides.** (1) Content: decide what text goes in, which nodes, what depth, the lead and the continuation, given the full tree and the narrative. This may go back and forth with the render. (2) Render, assuming the text is prepared. For now focus on the render, and set parameters for step 1 (length guidelines; ellipsis if a node is too long; some wrapping as in v0.1; an essay in a leaf won't work).
- **Static first.** The primary use is a static image embedded in web pages and reports. The interactive view is not the focus now. Mobile is not a constraint; readers may scroll.
- **Branch under the text looks bad** (markmap, MindNode, our current shelf design): "it really doesn't work… it's hard to then see the branches." Whimsical is okay (tidy, colour consistency) but not organic. Mermaid ugly. Consulting issue tree: boxes take a lot of attentional space; poor.
- **Coggle is really good**, but look at Coggle *trees*, not mind maps. Reference: the Coggle screenshot on the About page of web3.lifeitself.org. Its grey root boxes are fine.
- **What matters in the render:** the step-down ratio of font sizes by depth; a bold lead plus lighter text; a different colour per branch ("very clever"); branch thickness, taper, curvature and feel; how text wraps; the spacing of automatic layout.
- **Think information design broadly** (Tufte and other visual designers), not only mind-map apps: use the space efficiently, beautiful and good information design.
- **Method:** make several options, all mocked up on the same v0.1 text, and look at them side by side. Then keep rolling without checking in much.
- **Near-term milestone:** better trees, and a planned set of several trees for the Wise AI effort.

## Overall picture (revised)

1. **Content step** (later, separate part of the skill): full tree → prepared tree (chosen nodes and depth, lead + continuation, length limits). Guidelines now; tooling later.
2. **Render step** (now): prepared tree → beautiful static SVG/PNG for web pages and reports.
3. **Interactive view** (parked): the engine built 2026-11-08 keeps it, but no more work on it now.

The engine from 2026-11-08 (parser, canonical JSON tree, measurement, flextree layout, PNG, self-checks, CLI; `skills/tree-render/render/`) is kept. The drawing (shelf under text) and the themes are what change.

## What we do now

1. **References** (cheap model): capture the web3.lifeitself.org About Coggle tree and other Coggle *trees*; brief research on information design for trees beyond mind-map apps (Tufte, Lima's *Book of Trees*, editorial and scientific tree diagrams). Measure, one factor at a time: font ratios, branch widths and taper, curvature, text placement relative to the branch end, wrap widths, spacing.
2. **Options harness** (Opus): a parameterised static renderer on the existing engine, with no shelf under the text by default. Parameters: text attachment (the branch ends at the text's side, Coggle-style), font sizes per depth, lead weight, branch width per depth and taper, curvature, colour per branch, wrap width, spacing. Input: the v0.1 Q2 tree, converted to the canonical JSON.
3. **Options** (Fable, one focused run): 4–6 distinct options as parameter sets on the same v0.1 text, rendered, compared, critiqued; a recommendation. Published on one comparison page.
4. **Build** the recommended option as the default static renderer theme; content-step guidelines in the skill (lengths, lead + continuation, depth).
5. **Milestone:** propose a set of Wise AI trees (overview, Q1–Q4 hypothesis trees) and render them.

Rufus reviews the comparison page when convenient; the work does not wait on it.

## Second revision — 2026-11-12

Rufus on the Wise AI set (river and refined Coggle): "these look bad … nothing nearly as good as coggle and worse imo than v0.1 … can you start *exactly* copying coggle". Specifics: Coggle's branches curve twice (one way, then the other: a full S with horizontal ends); its colours are better; it colours the writing (each label in a darker shade of its branch hue).

New approach: stop interpreting Coggle and reproduce it. Extract Coggle's real drawing data (branch path geometry, widths, palette, fonts, text colours, spacing) from public diagrams in a browser, implement it as a faithful `coggle` mode, and verify by rendering the web3 About-page tree's own text and comparing it with the Coggle original side by side until they match. Only after that, adapt it to our content (lead + continuation).

## Third revision — 2026-11-12

Rufus on the exact-Coggle set: "this is *much* better and we now have a good 'coggle' style." Two asks: no branch should cross a label (done: the layout wraps interior labels narrower and lengthens runs only where a sibling group collides; see coggle-spec.md, "Our one deviation"), and next look for more "elegant", refined styles.

Candidate directions (Fable), each a few deltas from coggle-exact, keeping the S-curves, colour per branch and coloured text:

- **Hairline** (Tufte, least ink): IBM Plex Sans, lead 600; branch width ×0.5 (min 1.5 px); hues a little darker so thin lines carry colour; more air (ySpace 20, leaf offset 70); root box outline only. Risk: thin S-curves read weak rather than refined.
- **Broadsheet** (FT/Economist graphics desk): Source Sans 3, 18/15.5/13/12; saturation ×0.8; branch width ×0.85; root without a box, bold with a hairline rule. Risk: muting is where the earlier refined attempt lost.
- **Letterpress** (book typography on warm paper): Source Serif 4, 18/16/14/13, lead 600; exact Coggle palette and geometry; paper #fbf9f4, warm root box; continuation a darker shade of the lead's hue. Risk: small serif text looks fussy on screen; pastels may clash with warm paper.

Next: once Rufus OKs, mock all three on the same Wise AI tree beside coggle-exact on one page.

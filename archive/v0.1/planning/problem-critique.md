# Critique of problem.md v1 (subagent, 2026-10-17)

Ranked issues and fixes; how each was handled in v2 is noted in brackets.

1. **No audience or use case**, so "share" and "grasp" are untestable. Name 2–3 ranked uses (social post of one thesis; slide in a talk; one-page overview for collaborators) and trace formats and requirements to them. [Adopted: "Uses" section.]
2. **The binding constraint is writing, not drawing.** If every node has a short headline, layout is easy; if not, no layout saves it. Lead with it, and fix at source with an authoring rule (≤ 12-word headline per node). "One picture can't do everything" and "two views" are design tensions, not complications. [Adopted.]
3. **The question bundles two questions** and has an unmeasurable criterion ("people want to share it"). Make the question about the visual form for named uses; treat principles + skill as the deliverable; use "Rufus would post or present it as-is". [Adopted.]
4. **Persuade vs inform unresolved; SCQ missing from the visual.** For sharing, the stakes are the hook; Q2's asymmetry line persuades more than its pillars. Q always shown; C as a one-line kicker on overview and social formats; aim is inform with the logic visible; test that a reader can say *why* the claim follows. [Adopted as R2 and a working call.]
5. **Requirements not MECE.** Split visual vs skill requirements; unbundle R3; merge overlapping traceability; name the evaluation proxy (fresh vision-model subagent plus Rufus); add credit/link-back and in-progress status. [Adopted.]
6. **Three formats is premature.** Derive formats from uses; get one to post quality first. [Partly adopted: one format (branch poster) first to post quality, then the overview because the task explicitly asks for it; thesis card deferred.]
7. **"Not a tool" conflicts with repeatability.** Hand-placing coordinates for many nodes is where an AI is unreliable; allow a small layout helper or template inside the skill. "No product to maintain" is the real constraint. [Adopted.]
8. **Sub-questions miss prior art and evaluation, and layout/rendering are coupled.** Reorder: uses → prior art → text → formats/layout with rendering constraints → visual language → evaluation. Drop light/dark for posted images (they carry their own background). [Adopted; light/dark kept only for inline/web embedding.]
